# The rig

A router this release can be tested against, standing entirely inside WSL: an
OpenWrt VM under QEMU, a PPPoE server dialling five hundred sessions at it, and
five hundred DHCP clients in their own network namespaces.

It exists because the claims this release makes are about size. "Five hundred
sessions and five hundred bindings" is not something a probe can tell you: the
probes prove the arithmetic and the contracts, and what they cannot prove is
that a real kernel with fifteen hundred routing rules on it still answers a
netlink dump inside a pass.

```bash
rig/up.sh          # about two hours the first time, fifty minutes after
rig/verify.sh      # the matrix
rig/down.sh        # take it down, and prove the machine is as it was found
```

## The one thing to know before running it

This WSL shares its network namespace with the machine it is on. `eth1` in here
is a real Wi-Fi adapter on a real network.

So every interface, bridge, namespace and tap the rig creates is named `bmr-`,
`lib.sh:guard_name` refuses to touch anything else, and `up.sh` writes down what
the machine looked like before it started. `down.sh` diffs against that and
exits non-zero if the two differ. Nothing is ever enslaved to a bridge, deleted
or reconfigured unless its name begins `bmr-`.

The rig never touches the router at 12.10.10.1, or any other real router.

## What it builds

| Piece | What it is |
|---|---|
| `bmr-lan` | A bridge with no address. The VM's LAN and every client hang off it. |
| `bmr-wan` | A bridge with no address, carrying 500 VLANs (101-600). |
| `bmr-c001`..`c500` | One network namespace each, one veth into `bmr-lan`, `udhcpc` inside. |
| accel-ppp | Built from source, PPPoE only, listening on every `bmr-wan.N`. |
| The VM | OpenWrt 25.12.5 x86/64, 2 vCPU, 2 GB, three NICs: LAN, a host-forwarded WAN, and the carrier. |

The VM's LAN is `10.10.0.1/22` with a lease ceiling of 1500 and a range of 1000,
which is what makes five hundred clients possible at all - the stock 150 is
below the number this release is about, and that is itself one of the things the
capacity report says out loud.

## Getting in

`up.sh` prints both. The root password is generated by `openssl rand` into
`rig/.secrets/root-password` and typed nowhere else; the ssh key is
`rig/.secrets/id_rig`.

- LuCI: `http://localhost:8080`
- ssh: `127.0.0.1` port `2222`, with that key
- The Bored Manager app: add a machine at `127.0.0.1:2222`, user `root`, that key

`rig/.secrets/` and `rig/work/` are gitignored. Nothing in either is ever
committed.

## The matrix

`verify.sh` checks fifteen claims and prints the number behind each one. A claim
it cannot check - because no pool has been created yet, say - prints SKIP rather
than PASS. A matrix that turned "not measured" into a tick would be worse than
no matrix.

`verify.sh --calibrate` writes `work/calibration.json`: memory used at this
load, the reply sizes, the rule and neighbour counts, and the timings. Those are
the measurements the constants in `bm/capacity.uc` are meant to be fitted to.

## Calibration

Not done yet. Every constant in `bm/capacity.uc` marked `source: measured`
carries `calibrated: false`, and the capacity report says so in its own reply:

> Working numbers: no rig has measured this hardware yet, so treat the ceilings
> as a rough guide.

When a run does measure them, the numbers go into the `CONSTANTS` table with the
rig, the date, the architecture and the method in the header above it - and this
section says the same thing, copied from `work/calibration.json` rather than
typed.

## Cleaning up

`down.sh` stops the VM, stops accel-ppp, removes every `bmr-` namespace, veth,
VLAN, tap and bridge, and then compares three lists against the baseline:
`ip -br link`, `ip netns list`, and any process matching `bmr-|accel-pppd|qemu-system`.
It exits non-zero if any of them differs.

- `--purge` also removes `work/`, including the downloads and the build trees.
- `--purge-apt` also removes exactly the apt packages `up.sh` installed, which
  are listed in `work/installed.txt`. Packages that were already on the machine
  are never touched.
